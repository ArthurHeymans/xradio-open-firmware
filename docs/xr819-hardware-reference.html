1. Document control

This reference describes the XR819 as seen from the CPU core that runs its firmware: the register aperture, the descriptor formats the hardware consumes, and the order in which software must touch them for each functional flow. It exists because the register-level behaviour of this device is not published. Everything here was derived from the shipped vendor image, its decompilation, and experiments on real silicon.

1.1 Scope

  • Covered: platform blocks (interrupt controller, system control, clock/reset, timers, platform control), host interface (HIF), packet DMA and receive FIFO, MAC mode/response/TSF registers, the four MAC TX pipes, the AES/CCMP engine, and the PHY/RF window as far as its register semantics are known.
  • Not covered: SDIO host-side registers, RF transceiver internals, vendor upper-MAC algorithms (rate control, aggregation policy) except where they determine hardware sequencing.
  • Register offsets are given relative to their block base. Absolute addresses are used where the firmware itself uses absolute addresses; that distinction matters and is called out where it occurs.

2. Address map

The device exposes a sparse 32-bit physical address sparsely decoded into a handful of apertures. Code and data live in two tightly coupled memories (ITCM at 0, DTCM at 0x0400_0000); packet memory is a separate SRAM bank reached at 0x0900_0000; peripherals occupy 0x09c0_0000 to 0x0acc_0000; a small high SRAM at 0xfff0_0000 holds the vendor bootstrap.

Remap window relocation

The eight window descriptors are sampled by FUN_00015944. If any is nonzero, windows 3, 4 and 5 are rewritten with a relocated base: the page number (bits 12..27) is shifted, biased by 0x166 and written back, with window 4 also carrying the overflow into bits 28..31 and window 5 receiving the low nibble of that overflow. This is a fixed translation of the vendor algorithm and is reproduced exactly:

t3 = ((w3 & 0x0fff_ffff) >> 12) + 0x166
t4 = ((w4 & 0x0fff_ffff) >> 12) + 0x166
th = ((w4 >> 28) | (w5 << 4)) + 0x166
w3 = (w3 & 0xf000_0fff) | (t3 << 12)
w4 = (w4 & 0x0000_0fff) | (t4 << 12) | (th << 28)
w5 = (w5 & 0xffff_f000) | ((th & 0xffff) >> 4)

Window 0 is later read as the remap control word: if its bit 27 is clear, startup mode becomes 3 and the probe sequence runs.

6. Host interface (HIF): 0x0ab0_0000 and 0x0ab0_0100

The HIF is a descriptor-driven DMA engine between the SDIO function and packet RAM. It has two rings in opposite directions plus a dedicated emergency descriptor used by the fatal-exception path. Both rings are memory-mapped in the CPU's address space, so firmware behaviour is "publish a descriptor, then read the engine's status registers".

Ownership rule. A cleared descriptor control word alone is not a transfer-completion notification: the engine may clear it after fetching the descriptor but before the host has finished reading the buffer. Firmware must treat HIF status bit 1 as the completion event, and status bit 2 as the request-ready event, with the descriptor being reclaimed only afterwards. Vendor hif_tx_confirm_drain ordering is explicit: make the descriptor slot reusable and push its successor before releasing the completed message's backing storage.

7. Packet DMA and the receive FIFO (MAC +0x0600)

Packet DMA is the only writer of received frames. It appends complete 802.11 frames, each prefixed by a 0x20-byte header and followed by a 4-byte-aligned trailer, into the RX FIFO ring and advances a producer offset. The firmware reads the producer, claims slots, publishes a consumer offset, and releases buffers back to the HIF.

Offsets are logical: they wrap below 0x7000, and the FIFO keeps 0x1000 bytes of linear spill so that a slot starting near the top of the ring remains addressable. CPU access is always rx_fifo_base + (offset % 0x7000). The WSM message ceiling is 0x1ffe bytes. Subtract 16 bytes of host headroom for the frame limit (8174 bytes); the RX slot length may include another four FCS bytes (8178). The available bytes and physical storage must also cover the slot.

12.2 Platform bring-up order

The vendor fixes the order in 0x000164bc. It is not a suggestion: several blocks must be programmed before the memory and clock remapping they depend on, and two of them (the +0xac800bc update and the 0x0aa80004 = 0x200 transition) mark points after which earlier aliases stop working.

What 0x000009e0 does

  1. Sample all eight remap windows through 0x0aa80008/0x0aa8002c, and relocate windows 3, 4 and 5.
  2. If window 0 bit 27 is clear: set startup mode 3, set feature_control |= 0x0018_0200, clear system_control.control bit 5 and set bit 6, set secondary_control bit 6, then poll status bit 5. If it reads 0 (it does on this device), clear secondary_control bit 6 and drop startup mode to 1. Restore feature_control.
  3. Start timer 0 free-running: load 0xffff_ffff, prescale 0x4f, control 0x80. Prescale timer 1 to 0x4f, mode 0.
  4. Reset the interrupt controller: configuration 0x1600_a037, clear and acknowledge all sources, vector base, enable 0, control 1.
  5. Mask clock sources: mask_44 &= 0x7fff_f777, mask_48 &= 0x777f_ffff.

What 0x00000bb0 does

  1. Drain the write buffer, then reprogram system_control: clear bit 7, set bit 4; clear secondary_control bit 4.
  2. mask_48 |= 0xf0, mask_40 |= 0x00f0_0000.
  3. platform_control.shared_pointer = 0x0004_0090, power_control = 0x10, and (if no remap windows) configuration |= 0x0012_0000.
  4. clock_reset.control_04 = 0x200. After this write, the 0x0900ff98 alias may stop reading; that is a mapping change.
  5. parameter_a0 = 31, parameter_9c = 6, then poll ready_status bit 0 (bounded).
  6. clock_flags = 0x0c02 if clock_status bit 3 is clear, else 0x0042.

Trap: stack placement. The Rust stack must be in low SRAM across the 0x0aa80004 transition. An image that kept its stack in the 0xfffxxxxx window failed at exactly this step, and the failure looked like a packet-memory access fault. With the stack below the transition, the same code passes.

Three orderings that are not interchangeable even though the final register image is identical.

  • RX DMA +0x0c before +0x00: writing control first exposes the controller to a stale configuration word across the transition.
  • 0x0e34 zero then three: if the register has sticky or write-one-to-set bits, a direct write of 3 is a different event.
  • Debug context +0x00 last: writing the base first transiently publishes whatever +0x04..+0x10 held.

Each of these was a real bug that left the final values correct.

What the firmware must get right

  1. Producer read is a snapshot. Treat it as an upper bound, not a promise that everything below it is complete; validate magic and length before trusting a slot.
  2. Offsets are modulo 0x7000 on the CPU side, and a slot that starts near the end of the ring spills linearly into the next 0x1000 bytes of storage. Do not wrap a slot's interior.
  3. Release only what was claimed. Writing a larger consumer value than the slots actually processed loses frames silently.
  4. Return RX buffers in the order they were read. The radio publishes at most 24 FIFO slots before it takes them back, and the return queue is 64 entries of tokens.
  5. Resynchronization is real. When a slot's internal next pointer disagrees with the producer, the vendor re-derives the consumer by scanning for the next magic slot. Doing that too aggressively costs frames; not doing it stalls the ring.

Publication checklist

  1. Reserve the slot in the pipe registry (state 0), keeping the previous image so an abort can restore it.
  2. Build the descriptor completely before any MAC-visible write. The descriptor lives in a packet-RAM command slot owned exclusively by that pipe and slot index.
  3. Set the descriptor flags word and push the airtime word into the ring's duration FIFO.
  4. Write GO = 1 as the last write, after a write-buffer drain. The MAC fetching a partially written descriptor is not recoverable.
  5. Record the publication (pipe, slot, context, frame address, command base) so that start, status and completion events can be matched. A completion for an unowned slot must be rejected before any dereference.
  6. Advance on the event FIFO, not on the register readback: the pipe's cursor register can move before the event that describes the frame.

Why the descriptor is not a plain packet buffer. The MAC executes the command word stream. It can insert values (frame control, timestamps), source bytes (interface metadata), and split header from payload with different encodings, including a DMA bus address for the payload. That is what allows one descriptor template to serve beacons, ACK/CTS responses, BlockAcks and ordinary data.

classify frame | |-- wait for bit 12 clear before issuing a command; later stages also wait for bit 13 set |-- if key not loaded: 4 FIFO words (16 key bytes), then 0x1100 |-- write 16-byte CCM context block, then 0x1240 |-- write AAD stream: 2-byte BE length + AAD bytes, then 0x1403/0x1402 |-- write remaining AAD words and the length-specific tail command (TX values in §10.2; subtract one for RX) |-- source, destination, length |-- write barrier |-- start: 0x3008_1009 (TX) or 0x3008_1008 (RX) | |<-- IRQ 18 or 20 |-- read status: bit 0 is the MIC check for decryption |-- next queued operation (the engine is globally serialized)

Firmware invariants: one transfer at a time device-wide; key, AAD and payload storage retained until completion; DMA-visible uncached memory; a write barrier before the start word; bounded FIFO and command waits, treated as fatal until a reset sequence is known.

12.9 Interrupts and idle sleep

The firmware services interrupts but keeps FIQ masked. The MAC's event line is FIQ: it ends a wait-for-interrupt without ever appearing as a pending source.

_irq_handler (IRQ mode, IRQ+FIQ masked) pending = controller.pending controller.enable &= ~pending mask every pending source controller.acknowledge = pending clear them RAISED |= pending record for the owner main loop owner takes its bit from RAISED, clears the cause in its device, then re-arms its source idle path if nothing changed for 5 ms: arm timer 1 for the next deadline, mask IRQ, check once more, then WFI

Why the masking matters: a level source (HIF) cannot re-enter the handler before its owner ran, and a latched source (AES, timer) is not lost while its owner is busy. Main-loop state is never touched from the handler.

Linger and wake policy

While work is in flight (frames queued for the MAC, mid-decryption, held for reordering, or output the host has not read) a sleep lasts at most 1 ms: not every step raises an interrupt or names a deadline. After 5 ms of idle passes the loop sleeps until the next timed work: the pipe watchdog every 200 ms, beacon loss, an ADDBA response timeout, a missing BlockAck, the end of a scan dwell, or the next probe delay. A scan that tunes, settles or stops the radio keeps the loop awake.

13. Programming sequences

These are the sequences as checklists. Each step is a register write or a bounded poll; anything that must be quiescent is marked.

13.1 Cold bring-up

  1. Apply the five loader groups (4 copies + 41 MMIO pairs).
  2. Clear firmware .bss; initialize boot state (startup mode 1, no remap windows).
  3. 0x0ac8_00bc: clear bit 0, set bit 23.
  4. Sample and relocate the eight remap windows; run the memory probe and select startup mode.
  5. Start timer 0 (free-running), configure timer 1; reset the interrupt controller; mask clock sources.
  6. Drain; program system_control; set clock masks; shared_pointer, power_control, configuration |= 0x0012_0000 when applicable.
  7. clock_reset.control_04 = 0x200 (stack must already be in low SRAM).
  8. parameter_a0 = 31, parameter_9c = 6, poll ready_status bit 0, write clock_flags.
  9. HIF: publish the descriptor ring, enable IRQ 13, ack and set the length mask; the vendor routine waits for startup bit 10 to clear.
  10. Register IRQs 6, 18, 20; later 26.
  11. Packet DMA initialization (section 12.3), including the response list and MAC receive image.
  12. Enable the packet controller, build and send the startup indication.
  13. Enable IRQ/FIQ, apply the routing words, enter the scheduler.

13.2 Channel change

  1. Stop the radio: 0x0a28 = 0, 0x0a00 = 0x1030_0000, restore the beacon selector, point every response pointer slot at the idle descriptor.
  2. Drain RX in software; PHY command 7 for the new channel; program phy_set_band_reg.
  3. Publish the rate-RAM base at 0x09c0_0800; reprogram the rate tables of every active record; rebuild and reinstall the immediate response descriptors.
  4. Write the mode word 0x0200, then the filter/mask registers of section 8.2.
  5. Restore slot timings (a joined station uses a 9 µs base; the scan record's timing word is zero).
  6. Save the debug context at 0x1400..0x1410, base last.

13.3 Beacon start and stop

  1. build_beacon_descriptor(): response command 3 gets the gap word, fixed backoff, PHY words, frame control, payload address, timestamp macro, terminator.
  2. start_beaconing(): put an idle descriptor in pointer slot 0x10; write 0x0e94 with the airtime of 24 octets at the beacon rate.
  3. arm_beacon(tbtt): pointer slot 0 = response command 3, 0x0a00 = 0x1030_0001, 0x0e08 = 0x4000_0000 | (tbtt & 0x00ff_ffff).
  4. disarm_beacon(): 0x0e08 = 0, 0x0a00 = 0x1030_0000, pointer slot 0 = idle descriptor.

13.4 Publishing one HIF output message

  1. Check status bit 1 was seen since the last drain; confirm ring capacity (producer - consumer < 4).
  2. Write the message length and id into the buffer; rewrite the id with the two sequence bits.
  3. Write the descriptor: bus address, control = ((len+1) & 0x1ffe) | 1 plus sequence.
  4. Advance the producer.
  5. On status bit 1: for each descriptor whose control bit 0 is clear, in order, re-stage the next message before releasing the completed buffer.

13.5 Selective A-MPDU retry

  1. Validate the retained aggregate identity (two exact frame-node addresses, command base, pipe, slot).
  2. Decode the compressed BlockAck bitmap; members it rejects become retry candidates.
  3. For each candidate: validate the same identity again, build the transfer word, and re-arm the command mask bit.
  4. Re-publish with a fresh duration word and GO; count the retry against that pipe-slot key, not a global counter.
  5. On exhaustion, retire the member to a give-up pair and release its command mask.

Erratum 1: do not re-write the TX ring while the MAC is live. Writing ring+0x14 (GO) and cycling 0x0e8c during operation leaves the final values correct and corrupts fetch behaviour. The vendor programs these exactly once, before MAC core enable.

Erratum 2: TSF control is edge-sensitive in practice. Write 0x0e34 = 0 and then 3. A single write of 3 was the first deviation found in the vendor comparison and remains a suspected cause of rare TSF/event anomalies.

Erratum 3: the scan filter value excludes compressed BlockAck frames. The synthetic-scan mode word uses 0x0204 = 0x0019_8000, which drops received compressed BlockAcks from packet DMA even when the AP sends them and TX status completes. A joined station must use 0x0279_fe00.

Appendix A. Packet-RAM address encodings

The same storage has several hardware representations. They are not interchangeable, and mixing them produces silent corruption rather than a fault.

ClassShapeValid use
CPU runtime address0x0900_7000..0x0901_6630CPU loads/stores and software ownership records
CPU RX FIFO address0x0940_0000..0x0940_8000CPU access to FIFO slots after bounded offset normalisation
MAC 23-bit offsetcpu & 0x007f_ffffMAC registers and command-word operands
DMA/HIF bus addresscpu & 0xf6ff_ffffHIF, AES/MIC and packet-DMA descriptors
A-MPDU transfer0x6500_0000 | (cpu & 0x001f_fffc)MAC command streams only
RX FIFO logical offsetoffset < 0x7000Producer/consumer accounting only

A bus encoding is never a CPU pointer. Decoding a hardware word by OR-ing a CPU base, or using the masked value directly as a pointer, is invalid unless an independently owned CPU-form identity proves the target object. In the open firmware, production 0x007f_ffff and 0xf6ff_ffff masks exist only inside the packet-RAM module; every caller supplies a linker-owned root or an object base.
